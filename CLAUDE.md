# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`@xcrap/html-parser`: a Rust HTML parser exposed to Node.js via NAPI-RS. It supports CSS selectors (`scraper`) and XPath (`sxd_html` + `sxd-xpath`). Only a Windows x64 prebuilt binary is shipped.

## Commands

- `npm run build` builds the native addon in release mode and regenerates `index.js` / `index.d.ts`. `npm run build:debug` is the faster debug build.
- `npm test` runs ava (`__test__/*.spec.ts`, loaded through `@oxc-node/core`). Run a single file with `npx ava __test__/html-element-navigation.spec.ts`.
- Tests import `../index`, so **rebuild after any Rust change** or tests run against a stale binary.
- `npm run lint` (oxlint), `npm run format` (prettier + `cargo fmt` + taplo).
- Commits use Conventional Commits (see `CONTRIBUTING.md`). `Cargo.lock` is gitignored.

## Architecture

- `src/parser.rs`: `HTMLParser`. It holds the raw HTML and lazily builds two separate documents, a `scraper::Html` (wrapped in `Rc`) for CSS and an `sxd_document::Package` for XPath. Each is parsed only on first use of that query type.
- `src/engines.rs`: the select first/many functions for CSS and XPath, shared by the parser and by elements.
- `src/types.rs`: `HTMLElement` and the option/enum types exposed to JS.
- `src/query_builders.rs`: the `css()` / `xpath()` helpers that build `QueryConfig`.
- `index.js` and `index.d.ts` are generated by NAPI-RS. Do not hand-edit them; rebuild instead.

### HTMLElement model (non-obvious)

- An element stores `outer_html` plus an optional `NodeContext` (`Rc<Html>` + `NodeId`).
- **CSS results carry context.** They point into the shared parsed document, so navigation (`parent`, `ancestors`, `children`, `nextSibling`, `previousSibling`, `siblings`, `closest`, `firstChild`, `lastChild`) works and chains across `selectFirst` / `selectMany` calls.
- **XPath results have no context.** The XPath engine returns `node.string_value()` (text), not real HTML. Navigation returns `null` or `[]` for them.
- Property getters that don't need the tree (`id`, `tagName`, `text`, `attributes`, `innerHTML`, …) re-parse `outer_html` as a fragment on every call. Fragment parsing drops `<html>`, `<head>` and `<body>`, so those getters are wrong for those tags.
- Element-level CSS `selectFirst` / `selectMany` search descendants only when context exists. Elements without context fall back to fragment parsing, where the element matches itself too.
- `QueryType` is a `const enum` in the generated `index.d.ts`, so it does not exist at runtime. Tests import it with `import type`.
